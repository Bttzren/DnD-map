# DnD Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web app where a DM generates gridded encounter maps (built-in or AI), runs them live, and players watch on their own devices.

**Architecture:** One Node process (plain `http` + `ws`) serves the built client, a tiny HTTP API for creating games, and a WebSocket for sync. All game logic that both sides need (types, map builder, generators, op reducer, player-view filter, distance maths) lives in `shared/` and is imported by both server and client. The DM client applies ops locally and sends them; the server applies the same reducer, persists, and pushes each player a filtered view.

**Tech Stack:** TypeScript, Preact (via `@preact/preset-vite`), Vite, `ws`, `@anthropic-ai/sdk`, Vitest, esbuild (server bundle), Playwright (preinstalled) for the end-to-end script.

**Spec:** `docs/superpowers/specs/2026-11-16-dnd-map-design.md`

## Global Constraints

- Cells are 5 ft squares. Default map 40 x 30, maximum 80 x 80, minimum 10 x 10.
- Room code: 6 characters from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`; input is uppercased and stripped of spaces.
- DM secret: 32 random bytes, hex. Never sent to players.
- Player-bound data only ever comes from `playerView()`.
- AI: key from `ANTHROPIC_API_KEY`; model from `AI_MODEL`, default `claude-sonnet-5-5`; max 5 AI requests per minute per room.
- `HOST_PASSWORD` optional; when set, creating a game requires it.
- Rooms untouched for 30 days are deleted. Saves debounced to 1 s.
- Distance rules: `5e` (diagonal = 5 ft), `alt` (5/10 alternating), `euclid` (rounded to nearest foot).

## Review Focus

1. **AI returns a junk plan** (overlapping rooms, off-map coordinates, unknown terrain, zero rooms): the DM still gets a valid, fully connected map. Test in Task 2.
2. **Large token straddling fog**: a 2x2+ token is sent to players if any cell it covers is revealed, never otherwise. Test in Task 4.
3. **DM open in two tabs/devices**: an op from one reaches the other. Test in Task 5.
4. **Server restarts mid-session with an empty disk**: the DM's reconnect restores the room and players get the map again. Test in Task 5.
5. **Player types the code as `abc 123`**: joins `ABC123`. Test in Task 5.
